# AI-чат-агент для сайта

Встраиваемый чат-виджет на сайт бизнеса. Отвечает клиентам по услугам, ценам
и FAQ, используя AI (Claude или GPT). Вся специфика бизнеса настраивается в
одном файле — `config.py`. Работает на вашем сервере (VPS), не требует
постоянных платежей разработчику — только оплата токенов LLM (обычно
несколько рублей за 100 диалогов при использовании бюджетной модели).

## Что нужно для запуска

1. VPS (виртуальный сервер) с Docker — то же, что использовалось для
   Telegram-бота, если он у вас уже есть, можно разместить оба сервиса рядом.
2. API-ключ от Anthropic или OpenAI (см. ниже, где получить).
3. Домен или поддомен (например `chat.вашсайт.ru`) — по желанию, можно
   работать и по IP-адресу.

## Шаг 1. Получить API-ключ

**Если используете Claude (Anthropic):**
1. Зайдите на https://console.anthropic.com
2. Зарегистрируйтесь / войдите
3. Слева выберите "API Keys" → "Create Key"
4. Скопируйте ключ (он показывается один раз!)
5. Пополните баланс на вкладке "Billing" (минимально — 5$, хватит надолго
   для чат-виджета на бюджетной модели)

**Если используете OpenAI (GPT):**
1. Зайдите на https://platform.openai.com/api-keys
2. Создайте ключ, скопируйте его
3. Пополните баланс в разделе Billing

## Шаг 2. Настроить конфиг

Откройте файл `config.py` и замените:
- `BUSINESS_NAME` — название бизнеса
- `SERVICES` — список услуг и цен
- `FAQ` — частые вопросы и ответы
- `CONTACT` — телефон/телеграм для передачи "живому" человеку
- `WIDGET_COLOR` — цвет иконки чата (в HEX, например `#2563EB`)
- `LLM_PROVIDER` и `MODEL` — какой ИИ использовать (по умолчанию — Claude
  Haiku, это самая бюджетная и быстрая модель, для чат-виджета достаточно)

## Шаг 3. Указать ключ

1. Скопируйте файл `.env.example` в `.env`
2. Откройте `.env` и вставьте туда ключ из Шага 1:
   ```
   API_KEY=ваш_настоящий_ключ
   ```

⚠️ Важно: файл `.env` никогда никому не показывайте и не публикуйте на GitHub.

## Шаг 4. Запустить на VPS

Подключитесь к серверу по SSH и выполните по очереди:

```bash
# 1. Установить Docker (если ещё не установлен)
curl -fsSL https://get.docker.com | sh

# 2. Скачать проект на сервер (замените на свой способ загрузки,
#    например через git clone или загрузку архива)
cd /root
# ... поместите папку проекта здесь ...
cd ai-website-chat-agent

# 3. Запустить
docker compose up -d --build
```

После этого сервис будет доступен на `http://IP_СЕРВЕРА:8000`.

## Шаг 4.5. Настроить HTTPS (обязательно перед реальным использованием!)

Без HTTPS переписка клиентов с агентом идёт в открытом виде — любой в той же
сети может её перехватить. Это не подходит для реального сайта, только для
тестов. Проще всего закрыть это с помощью **Caddy** — он сам получает и
продлевает SSL-сертификат, без ручной возни с certbot.

Понадобится домен или поддомен, направленный на IP вашего VPS (A-запись в
настройках DNS, например `chat.вашсайт.ru → IP_СЕРВЕРА`).

1. На сервере создайте файл `Caddyfile` рядом с `docker-compose.yml`:
   ```
   chat.вашсайт.ru {
       reverse_proxy ai-chat-agent:8000
   }
   ```
2. Добавьте в `docker-compose.yml` сервис Caddy:
   ```yaml
   services:
     ai-chat-agent:
       build: .
       env_file:
         - .env
       restart: unless-stopped

     caddy:
       image: caddy:2
       ports:
         - "80:80"
         - "443:443"
       volumes:
         - ./Caddyfile:/etc/caddyfile
         - caddy_data:/data
       restart: unless-stopped

   volumes:
     caddy_data:
   ```
3. Перезапустите: `docker compose up -d --build`

Через минуту-две Caddy сам получит сертификат Let's Encrypt, и сайт будет
доступен по `https://chat.вашсайт.ru/widget.js` — этот адрес и нужно вставлять
клиенту в `<script src="...">`, а не голый IP.

## Шаг 4.6. Ограничить домен, с которого можно обращаться к чату

В `config.py` замените:
```python
ALLOWED_ORIGIN = "*"
```
на реальный домен сайта клиента:
```python
ALLOWED_ORIGIN = "https://сайт-клиента.ru"
```
Это не даёт посторонним сайтам дёргать API клиента напрямую и тратить его
бюджет на токены.

## Шаг 5. Вставить виджет на сайт клиента

В самый конец страницы (перед `</body>`) добавить одну строку:

```html
<script src="http://IP_СЕРВЕРА:8000/widget.js"></script>
```

Если настроен домен с SSL — используйте его вместо IP:
```html
<script src="https://chat.вашсайт.ru/widget.js"></script>
```

Готово — на сайте появится плавающая иконка чата.

## Проверить, что всё работает без сайта клиента

Откройте `http://IP_СЕРВЕРА:8000/demo` — это тестовая страница с уже
встроенным виджетом.

## Частые проблемы

| Проблема | Причина | Решение |
|---|---|---|
| Виджет не появляется | Скрипт не подключился | Проверьте путь в `<script src="...">`, откройте консоль браузера (F12) |
| Ошибка "API_KEY не задан" | Забыли создать `.env` | Скопируйте `.env.example` → `.env` и вставьте ключ |
| Агент отвечает не по теме / придумывает | Мало данных в конфиге | Дополните `SERVICES` и `FAQ` — агент отвечает только на основе этого |
| Дорого по токенам | Использована дорогая модель | Проверьте, что `MODEL` в config.py — бюджетная (Haiku / gpt-4o-mini) |
| 429 Too Many Requests | Сработал лимит защиты от спама | Это нормально при нагрузке — при необходимости увеличьте `RATE_LIMIT_PER_MINUTE` в config.py |

## Важно: персональные данные (152-ФЗ)

Если посетитель сайта пишет агенту телефон, имя или другие личные данные,
эти сообщения уходят на серверы Anthropic/OpenAI (они находятся за
пределами РФ) для обработки. Формально это передача персональных данных
за рубеж, и по 152-ФЗ у бизнеса-владельца сайта должна быть на этот счёт
явная политика конфиденциальности с согласием пользователя (обычно —
чекбокс или ссылка "продолжая переписку, вы соглашаетесь..." рядом с
виджетом чата, или пункт в общей политике конфиденциальности сайта).

Это ответственность и решение клиента-заказчика, не разработчика — но
лучше предупредить об этом на берегу, чтобы не было сюрпризов.

## Как это устроено (для разработчика)

- `config.py` — вся настройка бизнеса, единственный файл для правок
- `app.py` — backend на FastAPI: собирает системный промпт из конфига,
  обращается к LLM, отдаёт `widget.js`
- `static/widget.js` — сам виджет (иконка + окно чата), встраивается на
  любой сайт одной строкой
- История диалога хранится в браузере пользователя и передаётся с каждым
  запросом — backend не хранит состояние (проще и дешевле в поддержке)
